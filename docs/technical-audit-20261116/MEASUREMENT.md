# Схема будущего измерения в Google

Статус: подготовка, без подключения GA4. Яндекс в этой задаче не меняется и не используется для оценки результата.

## События

| Точка в существующем коде | Смысл | Возможное событие GA4 после отдельного подключения | Параметры |
|---|---|---|---|
| `lead_form_view` | Форма попала в видимую область | `view_lead_form` | `form_id`, путь страницы |
| `lead_form_open` | Первое взаимодействие с формой | `form_start` | `form_id`, тип страницы |
| `lead_form_submit_attempt` | Валидная форма передана в запрос провайдера | `lead_submit_attempt` | `lead_id`, `service`, `lead_type`, `source_cta`, объект/ЖК |
| `lead_form_success` | Провайдер вернул успешный HTTP-ответ и `success: true` | `generate_lead` | `lead_id`, услуга, источник CTA, идентификатор объекта/ЖК |
| `lead_form_error` | Ошибка конфигурации, сети или ответа провайдера | `lead_submit_error` | `lead_id`, категория ошибки |
| `phone_click` и существующие клики по каналам связи | Намерение позвонить или открыть мессенджер | `contact_click` | Канал, путь страницы, объект/ЖК при наличии |

Таблица задаёт контракт будущего адаптера. Текущие вызовы аналитики передают не все предлагаемые параметры. Реализация адаптера, GTM/GA4, consent и проверка DebugView относятся к отдельному подключению. Наличие этих вызовов в коде не подтверждает доставку событий в Google.

`generate_lead` — принятие формы провайдером, а не квалифицированный клиент или сделка. Клик по телефону не является разговором. Начало формы не является отправкой.

## Поля обращения и согласованность

В письмо уже передаются `lead_id`, `session_id`, `service`, `lead_type`, `source_cta`, `first_landing`, `initial_referrer`, referrer текущей страницы, доступные UTM и контекст объекта/ЖК. Пустой источник остаётся пустым: Google не подставляется по догадке.

| `service` | Допустимый `lead_type` / окончание темы |
|---|---|
| `buy` | `buy`; `newbuild` при покупке конкретного ЖК |
| `sell` | `sell` |
| `rent` | `rent` |
| `mortgage` | `mortgage` |
| `consultation` | `contact`; `construction` или `commercial` для соответствующей консультации |
| `valuation` | `valuation` у формы предварительной оценки |

Явно выбранная услуга перекрывает устаревший тип из CTA. Тема письма формируется из окончательного `lead_type`.

## Связь с журналом

При появлении журнала ключом одной отправки служит `lead_id`. Повторные письма или попытки с тем же ID сверяются как одна группа, с отдельными временем и результатом доставки. Не удалять сообщения без проверки цепочки. Один человек может создать разные обращения с разными ID; идентификатор отправки не является идентификатором человека.

Для строки обращения достаточно хранить `lead_id`, дату, услугу, тип, объект/ЖК, доступный источник, результат квалификации и следующий шаг. `session_id` связывает события браузера и письмо при доступном хранилище; сам по себе не доказывает связь с Google. При блокировках хранилища и аналитики полнота связи ограничена.

Имена, телефоны, email, текст обращения и URL с персональными параметрами не передаются в события Google. Полный `page_url` из письма нельзя автоматически копировать в аналитику. Для событий используются нормализованный путь страницы и разрешённые поля.

Источник Google можно считать подтверждённым только при доступном соответствующем referrer/кампании или согласованной аналитической цепочке. При неопределённости — `unknown`. До внедрения и проверки GA4 в отчёте Google нет измеренной воронки. Нельзя делить число писем на клики Search Console и называть это конверсией.
