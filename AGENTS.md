# DomianKvartal

Публичный сайт агентства недвижимости «Домиан Квартал» в Аксае работает на `domian-161.ru`. Репозиторий — `LeSauteur/DomianKvartal`, основная ветка — `main`. Основные разделы: главная, каталоги квартир, домов, участков, коммерции и аренды, карточки объектов, новостройки, строительство, услуги, «Гид» и команда.

## Исходники и сборка

- Редактируй статические HTML, CSS, JS и медиа в `public/`. Общие стили, скрипты и ресурсы лежат в `public/assets/`. Исходные страницы команды и «Гида» лежат в `public/team/` и `public/guides/`.
- Основной реестр объектов — `src/data/listings.json`, настройки сайта и маршрутов — `src/data/site.json`. Код подготовки карточек, страниц объектов и витрин находится в `src/`, шаблоны — в `src/templates/`. Проверяй потребителя данных перед изменением других JSON в `data/` или `public/`.
- `npm run build` собирает `dist/` из `public/`, реестра и шаблонов. На этапе сборки `src/site-theme.mjs` добавляет `wine-theme.css` в страницы с `main.css`.
- `npm run build:catalog` собирает сайт и синхронизирует корневые файлы для GitHub Pages. Их состав фиксирует `src/data/pages-root.json`. Правь источник и обновляй корневые копии сборкой. Перед коммитом проверь diff синхронизации.
- GitHub Pages публикует корень `main` через Jekyll с исключениями из `_config.yml`. В `.github/workflows/seo-qa.yml` CI запускает `npm run qa:static`, проверку паритета, проверку артефакта Pages и браузерные тесты. Для локальной проверки используй те же команды, включая `npm run check:parity`. `npm run qa:static` включает `npm test` и `npm run check:pages`. Для браузерной матрицы CI задай `VISUAL_TOP_QA=1` и запусти `npm run test:browser`.

## Стили и проверка темы

- `main.css` задаёт базовую типографику, переменные и общие компоненты. `visual-premium.css` содержит общие визуальные правила и оформление разделов, включая унаследованные объявления с `!important`. `wine-theme.css` задаёт палитру обеих тем и уточняет оформление общих компонентов. `home-wine.css` содержит отдельное оформление главной. Геометрия карточек команды находится в `agent.css`.
- Используй действующие переменные `--bg-surface`, `--text-main`, `--text-muted`, `--accent` и соседние токены темы. Проверяй порядок подключения, область действия и специфичность селекторов. Если общее правило с `!important` уже управляет свойством, предпочитай передать ему локальное значение через переменную. Сохраняй геометрию, типографику и действующие настройки каталога и главной.
- Проверяй обе темы через штатное переключение или `localStorage` с ключом `domian-color-theme`. Проверяй вычисленные цвета текста, фона, ссылок, кнопок и значимых иконок с учётом прозрачности и состояний hover/focus. Минимальный контраст WCAG AA — 4,5:1 для обычного текста и 3:1 для крупного текста и значимых элементов интерфейса. Проверяй ширины 1366, 390 и 360 px, включая переполнение и наложение карточек.

## GitHub и публикация

- Проверь `git status --short`, ветку и `origin`. Получи актуальный `origin/main` через успешный `fetch` и начни работу в ветке `codex/`. При незавершённых изменениях создай отдельный worktree от проверенного ref. Сохраняй рабочие материалы и пользовательские данные. Разрушительные Git-команды и перезапись правок требуют отдельного разрешения.
- Для GitHub используй Git по HTTPS и `gh`. В проверенном Windows-окружении Git использует `http.sslBackend=openssl`. При EOF или ошибке TLS проверь DNS, TCP 443, `git ls-remote` и API отдельно. Лимит — две контролируемые попытки одного способа для одной операции, затем меняй способ диагностики. EOF сам по себе не подтверждает проблему с авторизацией. Сохраняй проверку TLS и текущую конфигурацию сети. Для перехода к браузеру при работе с GitHub требуется отдельное разрешение.
- Публикуй по прямому поручению. После проверок и `git diff --check` сделай коммит, выполни `git push -u origin <ветка>`, создай один PR через `gh pr create --base main --head <ветка>` и дождись успеха `gh pr checks <PR> --watch --interval 10`. Сливай через `gh pr merge <PR> --merge --delete-branch`. Обнови чистую локальную `main` через `git pull --ff-only origin main`. При занятой рабочей копии получи merge-коммит через `fetch` и проверь его в изолированном worktree.
- Найди запуск Pages для точного merge SHA через `gh run list --limit 5`, проверь его через `gh run watch <ID> --exit-status` и проверь затронутые публичные URL через HTTPS. Для публикации используй существующие GitHub Pages и `origin`. Прямой push в `main`, Sites и смена хостинга исключены из штатного процесса.
